# ztingwei.com

Source for [Tingwei Zhang's](https://ztingwei.com) academic website — built with
[Hugo](https://gohugo.io) and the [Wowchemy Academic](https://wowchemy.com) theme,
deployed on Netlify.

## Local development

Requires Hugo **extended** 0.108.0 (matching `netlify.toml`) and Go (the theme is
pulled in as a Hugo Module, so the first build needs network access).

```bash
./view.sh              # hugo server with i18n warnings
hugo --gc --minify     # production build into public/
```

## Layout

| Path | Purpose |
| --- | --- |
| `config/_default/` | Site config: `config.yaml`, `params.yaml`, `menus.yaml`, `languages.yaml` |
| `content/authors/admin/` | Profile shown by the About section (bio, avatar, social links) |
| `content/home/` | Homepage sections. Only files with `active: true` are rendered |
| `content/publication/` | One folder per paper, each with `index.md` and `cite.bib` |
| `content/mynews/` + `content/newslist.dat` | News page; the `.dat` file holds the shared news entries |
| `content/fish/` | Unlisted fish log at `/fish/`; one folder per catch under `catches/` |
| `content/admin/` | Enables the CMS admin panel at `/admin/` |
| `data/themes/` | Custom color themes (`my_theme` is the active one) |
| `data/wowchemy_cms_tpl.yaml` | Defines which collections the admin panel exposes |
| `layouts/shortcodes/` | `readfromfile` |
| `static/files/` | CV, slides, and posters |
| `netlify/functions/` | Netlify serverless functions |

## Common edits

- **Add a publication:** create `content/publication/<slug>/index.md` (copy an existing
  one for the front matter shape) plus a `cite.bib`. It appears automatically on the
  homepage and at `/publication/`.
- **Add news:** append a line to `content/newslist.dat`.
- **Change the bio or social links:** `content/authors/admin/_index.md`.
- **Show/hide a homepage section:** toggle `active` in the relevant `content/home/*.md`.

Author names in publication front matter must be spelled identically across files,
otherwise Hugo generates a separate author page for each spelling.

## Fish log

The gallery at `/fish/` is deliberately unlisted: it's kept out of the nav, the
sitemap, the search index, and every list page, but stays reachable by direct URL.
This is obscurity, not access control — anyone with the link can read it.

Each catch is a folder under `content/fish/catches/` holding an `index.md` and its
photo. Thumbnails are generated by Hugo, and the full-size originals are never
published, so uploading straight off a phone is fine.

Catches are grouped on the page by their `location` value, so keep the spelling
consistent — `Cayuga Lake` and `cayuga lake` become two separate groups.

### Adding a catch

Go to `/admin/`, sign in, and use **New Catch**. Fields: species, date, location,
photo, length, weight, and notes — only species, date, and location are required.
Publishing commits to `main` and Netlify redeploys.

To add a new field, add it to the `fish` collection in `data/wowchemy_cms_tpl.yaml`
and render it in `layouts/fish/list.html`. Existing entries without the field keep
working. Avoid Hugo's reserved front matter names (`weight`, `title`, `type`,
`date`, `slug`) — that's why the size fields are `catch_length` and `catch_weight`.

### Editing the log locally

The admin panel can run against local files instead of GitHub, with no login. In
two terminals:

```bash
npx netlify-cms-proxy-server   # terminal 1
./view.sh                      # terminal 2
```

Then open <http://localhost:1313/admin/>. Saving writes directly to `content/fish/`
on disk. (`hugo server` sets the development environment, which is what turns the
local backend on.)

## Admin panel access

`/admin/` is published but gated by Netlify Identity. One-time setup in the Netlify
dashboard:

1. **Identity → Enable Identity**
2. **Identity → Services → Git Gateway → Enable**
3. **Identity → Registration → Invite only**
4. Invite your own address and accept the email

Step 3 is the one that matters. With registration left **Open**, anyone on the
internet can create an account and Git Gateway grants them commit access to this
repository.

### Why that access is worth guarding

Commit access here is not limited to editing Markdown. `netlify/functions/` is
deployed server-side code, and those functions read `SUPABASE_SERVICE_ROLE_KEY`
and `CANARY_CHECK_SECRET` from the Netlify environment. Anyone who can push to
`main` can deploy a function that exfiltrates them, and the Supabase service role
key bypasses Row Level Security. So a CMS account is effectively database access.

Keep registration invite-only, and keep two-factor auth on both the GitHub and
Netlify accounts.

### Pinned CMS bundle

`layouts/wowchemycms/single.html` overrides the module's admin shell so the Netlify
CMS bundle is pinned to an exact version and verified with a Subresource Integrity
hash, rather than tracking the floating `netlify-cms@2` tag. Upgrade instructions
are in the comment at the top of that file. Note that Netlify CMS is no longer
maintained upstream — Decap CMS is its successor, should a migration ever be needed.

## Theme updates

The theme version is pinned in `go.mod` / `go.sum`:

```bash
hugo mod get -u ./...   # update modules
hugo mod tidy
```
